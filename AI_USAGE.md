# AI usage

## Tools

| Tool | Model | Used for |
|---|---|---|
| Claude Code (VS Code extension) | Claude Opus 5.5 | Planning, code, tests, docs |
| A second Claude Code session, briefed as an independent reviewer | Claude Opus 5.5 | Reviewing the plan before coding, and the finished repo before submitting |

- **Agent instructions:** [`CLAUDE.md`](CLAUDE.md). It covers:
  - the layer rules
  - "the contract fixtures are the spec"
  - tests and `scripts/check.sh` before calling anything done
  - no new dependencies or commits without approval
- **Plan:** [`docs/PLAN.md`](docs/PLAN.md), written and reviewed before any code.

## How I worked with it

- **The decisions stayed mine.** The agent listed every gap in the requirements, each with a proposed assumption and an alternative. I chose. Design-changing choices were never left to the agent.
- **One feature at a time.** Each feature was committed only after its tests passed and I had tried it on the simulator against the real backend.
- **Reviews were independent and checked.** The reviewer was briefed to challenge, not approve. Each finding was verified against the code or the live API before acting on it, and wrong findings were rejected.
- **Rules were made executable.** Layer boundaries, styling and formatting are checked by `scripts/check.sh`. Each check was shown to fail on a planted violation before it was trusted.

## Key prompts

1. **Plan first.**
   > *"Do NOT write code yet. … Every gap in the acceptance criteria. For each one: your proposed assumption and one alternative. I will choose. … If a choice changes the design, ask me instead of guessing."*

2. **Critique the plan.**
   > *"You are designing this … as a lead/staff engineer would do?"*

   It found real gaps:
   - no build order
   - the API contract written twice, once per side
   - an untested tooling claim

   The shared contract fixtures and the "thin slice first" build order came from this.

3. **Independent review before coding.**
   > *"If you act yourself as a lead and one subagent acting like staff engineer and discuss this task … come up with solid plan and fill up the gaps … while being thorough."*

   The reviewer found the three biggest design problems (#1–#3 below).

4. **Independent review before submitting.**
   > *"Review the project entirely, docs and others. Think as a lead staff engineer."*

   It found:
   - doc claims the code didn't back up
   - an enquiry that could be sent without the customer knowing (#5)
   - a styling rule that missed cases (#6)

   Two of its findings were wrong, and were rejected with evidence.

A moment worth noting: **the contract fixtures caught a real mismatch on their first run.** They are generated by [`contract/generate_fixtures.py`](contract/generate_fixtures.py), separately from the backend. The backend trimmed a trailing space from an upstream title and the fixtures didn't. Trimming became a written contract rule, rather than a fixture edited to make a test pass.

## Where the AI got it wrong

| # | Mistake | Caught by | Fix |
|---|---|---|---|
| 1 | "Top rated" had two meanings: hand-picked on Home, computed from stars on category pages. | Plan review | One meaning: the products the business chose |
| 2 | Search used substring matching. "men" matched 13 of 20 products, including women's items. | Plan review | Match at the start of a word |
| 3 | API tests would have run on a fake product source with its own copy of the search code. | Plan review | Tests run the real adapter on a committed snapshot |
| 4 | The boundary script passed three rules without running them: an empty array under `set -u` in bash 3.2, with the error hidden. | A warning line in the script's own output | Errors now fail the check; every rule is proven by a planted violation |
| 5 | Cancel worked while an enquiry was sending, and the app timed out before the server. An email could be sent while the customer saw an error, and they'd send it again. | Final review | Cancel disabled while sending; server timeouts inside the app's |
| 6 | Two literal styles were left in views, and the style rule missed them. Its first widened pattern used `\b`, which `git grep` here doesn't support. | Final review, then proving the rule | Styles moved into the Theme; the rule was rewritten and proven |

Smaller ones fixed along the way:
- a missing peer dependency (`vite`)
- a regex that title-cased "men's" as "Men'S"
- an access log that dropped the `/v1` prefix
- an empty upstream list wiping the cache
- a double-tap test that didn't hold the request open
